# VAPT Lens — shared build spec (v1)

Guided, **read-only** VAPT assistant. It observes a page, optionally reads Burp traffic you import,
and suggests what to test and how. It NEVER sends attack payloads, never exploits, never logs in,
and never transmits form values, cookies, tokens, or credentials.

## Data contracts

### PageObservation (produced by `extension/src/core/scanner.js`)

```js
{
  capturedAt: string,            // ISO
  url: string, origin: string, host: string, path: string,
  title: string,
  queryParams: [{ name, valueLength }],   // NO values
  technologies: [{ name, evidence }],
  headers: [{ name, value }],    // allowlisted header names only; sensitive values redacted
  cookies: [{ name, httpOnly, secure, sameSite, valueLength }], // NO values
  forms: [{ action, method, enctype, hasFileInput,
            fields: [{ name, type, id, placeholder, required, maxLength }] }],
  links: [{ href, kind }],       // internal | external | suspicious
  scripts: [{ src, inlineLength }],
  endpoints: [{ url, source }],  // from links, scripts, inline regex
  domSinks: [{ type, evidence }],
  signals: {                     // booleans used by rules
    hasForm, hasTextInput, hasFileInput, hasLogin, hasSearch, hasUpload,
    hasGraphql, hasApiBase, hasRedirectParam, hasDebugParam, hasIdParam,
    hasUrlParam, hasJsonBodyHint, hasJwt, hasSessionCookie, hasCsp,
    hasMissingSecurityHeaders, hasInlineScript, hasDomSink, hasCsrfTokenField
  },
  counts: { forms, inputs, links, scripts, endpoints }
}
```

Rules for scanner:
- Never read or store form field **values**, `document.cookie` values, localStorage/sessionStorage values, or URL fragments that look like tokens. Only names, types, lengths, flags.
- Header capture happens in background via `webRequest` (allowlist: content-type, x-frame-options, content-security-policy, strict-transport-security, x-content-type-options, referrer-policy, permissions-policy, server, x-powered-by, cache-control). Redact anything containing `token|key|secret|auth|session|bearer` in value.
- Cookie flags need `cookies` permission; fetch only for current tab host at scan time. Never include cookie values.
- Inline script inspection is regex-only for sink names and API patterns; truncate evidence to 160 chars.

### BurpItem

```js
{ method, url, host, path, queryParams: [string], bodyParams: [string],
  headers: [{name, value}], status, contentType, length, source }
```

### AnalysisRequest / AnalysisResponse

```js
// POST /api/analyze
{ observation: PageObservation,
  traffic: BurpItem[],
  options: { ai: boolean, maxCards: number, authorized: boolean } }

// response
{ summary: { tech: [string], surface: object, riskHints: [string] },
  cards: [{
    id, category, title, severityHint, whyHere, steps: [string],
    payloads: [{ label, value }], playbookId, verify, defense, skillId, source: 'local'|'ai'
  }],
  aiUsed: boolean, generatedAt: string, warnings: [string] }
```

Cards must be **guidance only**: steps describe what to try manually in Burp/browser; payloads are
copyable safe test strings; no code that sends requests. Each card must cite a `skillId` when derived
from the offline KB.

### KnowledgeBase (generated)

```js
{ generatedAt, skills: [{
    id, name, description, triggers: [string], categories: [string],
    sections: [{ heading, bullets: [string], codeBlocks: [string] }],
    sourcePath
  }],
  rules: [{ id, when: { any?: string[], all?: string[] }, skillIds: [string],
            category: string, priority: number }] }
```

Signal keys in `rules.when` are dotted paths into the observation, e.g.
`signals.hasForm`, `signals.hasGraphql`, `queryParams[].name`, `cookies[].name`, `headers[].name`,
`technologies[].name`. Core rules live in `scripts/build-kb.mjs` and are emitted into the KB so the
bridge stays data-driven.

## Bridge HTTP API (default http://127.0.0.1:8787)

- `GET  /api/health` → `{ ok, kbSkills, version }`
- `GET  /api/kb` → KB (or `?summary=1`)
- `GET  /api/kb/skills/:id` → single skill
- `POST /api/analyze` → AnalysisResponse (local rules always; AI when `options.ai && AI enabled`)
- `POST /api/burp/import` `{ host, source, raw }` → `{ ok, count, items }`; stores by host
- `GET  /api/burp/traffic?host=...` → `{ items }`
- `POST /api/burp/stream` BurpItem → appends live item
- `DELETE /api/burp/traffic?host=...`
- `GET  /api/config`, `POST /api/config` (aiEnabled, model, port-independent config)

CORS must allow `chrome-extension://*`, `moz-extension://*`, `http://localhost:*`, `http://127.0.0.1:*`.
Body limit ~5 MB. All parsing failures return JSON errors.

## AI layer (`bridge/lib/ai.mjs`)

Use child process: `opencode run --format json --title "VAPT Lens analysis" <prompt>` with a 90 s
timeout. Parse newline-delimited JSON events; concatenate `part.type === 'text'` `.text` values;
extract the first JSON object/array from the text (strip markdown fences). Redact the observation
before sending: drop cookie/header values, keep names/flags/booleans; truncate to ~12k chars.
Prompt asks for JSON matching `cards[]` above, guidance-only, no exploitation, cite skill ids.
On any failure return `{ ok:false, error }` and bridge falls back to local cards with a warning.

## Safety / UX rules

- Panel shows a one-time **"I'm authorized to test this target"** checkbox. Cards are hidden until checked.
- Floating overlay: small orb bottom-right; click toggles panel (Chrome side panel / Firefox sidebar).
- Scanner never modifies the page; overlay uses Shadow DOM to avoid page CSS/JS interference.
- Never display or store secret-looking values. Notes are local (`chrome.storage.local`).
- UI copy must state: guidance only, no attacks performed, test only systems you own or are authorized to test.

## Build / run

- `npm run kb` → regenerate KB
- `npm run build` → build KB + dist/chrome + dist/firefox
- `npm run bridge` → start local bridge
- `npm test` → node:test suites
- Load unpacked `dist/chrome` in Chrome/Chromium via chrome://extensions (Developer mode).
  Firefox: `about:debugging` → Load Temporary Add-on → `dist/firefox/manifest.json`.
